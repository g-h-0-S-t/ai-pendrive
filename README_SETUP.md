# AI Pendrive — Setup Guide

This document explains the new setup system. If you are a new user, **just double-click `setup.bat`** and follow the prompts.

## What's new

| File | Purpose |
|---|---|
| `setup.bat` | Entry point for the setup wizard. Double-click this. |
| `setup_core.ps1` | The wizard engine (AUTO and SEMI-AUTO modes). |
| `detect_system.ps1` | Detects CPU, RAM, GPU, and recommends a profile. |
| `download_model.ps1` | Downloads a GGUF from Hugging Face (supports HF token). |
| `launcher.bat` | Unified launcher. Reads `config.json`. Has a menu for model switching and settings. |
| `launcher_core.ps1` | Launcher engine. |
| `config.json` | Generated by setup. Read by launcher and status dashboard. |
| `status.bat` | Now reads `host`/`port` from `config.json`. |

The old `start_*.bat` files are kept for compatibility but are no longer needed.

## First-time setup

1. Plug in the pendrive (or copy the folder anywhere).
2. Double-click **`setup.bat`**.
3. Choose:
   - **AUTO** — one-click. Detects hardware, downloads the right runtime and model, writes `config.json`. Best for new users.
   - **SEMI-AUTO** — guided. You pick the model, tier, context size, tools, port, etc. Defaults are pre-filled from detection.
4. When setup finishes, double-click **`launcher.bat`** to start the server.

## Daily use

1. Double-click **`launcher.bat`**.
2. From the menu:
   - **Start the server now** — launches llamafile and opens the browser.
   - **Change model** — pick from models already downloaded in `models\`.
   - **Add a new model from Hugging Face** — paste a URL and download it.
   - **Edit launch settings** — change CTX, PREDICT, threads, GPU layers, port, tools, etc.
   - **Re-run full setup wizard** — starts `setup.bat` again.
3. In another window, double-click **`status.bat`** for the live dashboard.

## Adding a custom model

In `launcher.bat`, choose **Add a new model from Hugging Face** and paste one of:

- A resolve URL: `https://huggingface.co/<user>/<repo>/resolve/main/<file>.gguf`
- An `hf://` URI: `hf://<user>/<repo>/<file>.gguf`
- A bare `user/repo/file.gguf` (supported by the wizard's custom option)

You will be asked which tier folder to save into (`4GB`, `6GB`, `8GB`, `no_gpu`, or `custom`).

For gated repos, enter your Hugging Face token when prompted. It can be saved to `.hf_token` (gitignored) for future runs.

Create a token at <https://huggingface.co/settings/tokens>.

## How AUTO mode decides

The wizard reads:

- **CPU** physical core count → `threads`
- **System RAM** total → tier safety floor (8 GB min for tier 4, 12 GB for 6, 16 GB for 8)
- **GPU vendor + VRAM** via `nvidia-smi` (NVIDIA) or `Win32_VideoController` (AMD)

Recommendation logic:

| Detected VRAM | Recommended tier | Model |
|---|---|---|
| ≥ 7.5 GB | `8` | Qwen3.5 9B Q4_K_M |
| ≥ 5.5 GB | `6` | Qwen3.5 4B Q4_K_M |
| ≥ 3.5 GB | `4` | Qwen3.5 2B Q8_0 |
| < 3.5 GB or no GPU | `no_gpu` | Qwen3.5 2B Q4_K_M |

If system RAM is below the tier floor, the wizard downgrades to `no_gpu` automatically.

## config.json

Written by `setup.bat`, read by `launcher.bat` and `status.bat`. Example:

```json
{
  "generatedAt": "2026-10-08T21:21:07",
  "tier": "8",
  "modelPath": "models\\8GB\\Qwen3.5-9B-Uncensored-HauhauCS-Aggressive-Q4_K_M.gguf",
  "host": "127.0.0.1",
  "port": 8080,
  "context": 262144,
  "predict": 32768,
  "parallel": 1,
  "threads": 8,
  "gpuLayers": 999,
  "batch": 128,
  "ubatch": 128,
  "cacheK": "q4_0",
  "cacheV": "q4_0",
  "useNoMmap": true,
  "flashAttn": "on",
  "enableMetrics": true,
  "enableTools": true,
  "tools": "all",
  "browserTimeoutMin": 30,
  "llamafilePath": "server\\llamafile-0.10.5.exe"
}
```

Delete it to force the wizard to run again, or edit it by hand.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `setup.bat` closes instantly | Run it from a Command Prompt to see the error. Usually a missing PowerShell or blocked execution policy. |
| Runtime download fails | Download `llamafile-0.10.5` manually from the GitHub releases page and save it as `server\llamafile-0.10.5.exe`. |
| Model download fails on a gated repo | Add your HF token during setup, or save it to `.hf_token`. |
| Launcher says "config.json missing" | Run `setup.bat` first. |
| Browser does not open | Wait for the model to load. It can take 10–30 minutes on CPU. Open `http://127.0.0.1:8080/` manually. |
| Port already in use | Use **Edit launch settings** in `launcher.bat` to change the port, or close the other process. |
| Out of memory during load | Lower CTX (e.g., 196608 → 131072 → 65536), or reduce BATCH/UBATCH from 128 to 64, or pick a smaller model. |
| `request exceeds the available context size` | Raise CTX. The bundled web UI sends a large system prompt on every request. |
| GPU layers mismatch | Check the launcher's startup log for `offloaded X/Y layers to GPU`. |

## Security notes

- The server binds to `127.0.0.1` by default — only the local machine can reach it.
- When agent tools are enabled, `exec_shell_command` lets the model run arbitrary commands. Only enable tools on a trusted, isolated machine.
- Never expose port 8080 to the network with tools enabled.
- `.hf_token` stores your token in plaintext. It is gitignored but is still on the pendrive. Treat the pendrive as sensitive.
