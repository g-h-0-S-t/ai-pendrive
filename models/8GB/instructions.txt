================================================================================
AI Pendrive - 8 GB VRAM Models
================================================================================

This folder contains GGUF model files used by the 8 GB profile in start.bat.

Current start.bat model path for TIER=8:

  models\8GB\Qwen3.5-9B-Uncensored-HauhauCS-Aggressive-Q4_K_M.gguf

That filename and location must match exactly unless you edit MODEL_8GB in
start.bat.

The current launcher is intentionally simple:

  - It does NOT download models automatically.
  - It does NOT scan this folder and offer a model picker.
  - It does NOT auto-detect your GPU.
  - You choose the preset yourself with: set "TIER=8" in start.bat.

================================================================================
WHO THIS IS FOR
================================================================================

Use this profile for NVIDIA GPUs with approximately 8 GB of dedicated VRAM.
Examples include RTX 2070, RTX 2070 Max-Q, RTX 2080, RTX 3060 8 GB, RTX 4060
8 GB, and similar cards.

The default configuration uses:

  Context window:  64K tokens (CTX=65536)
  Parallel slots:  1
  GPU layers:      999 (try to offload every layer that fits)
  KV cache:        q8_0 for keys and values
  Flash Attention: on
  Metrics:         enabled for status.bat

64K is a demanding long-context target. Whether a model is fully GPU-resident
at 64K depends on its architecture, GGUF quantization, GPU driver, background
VRAM use, and KV-cache size. Always test the exact model with start.bat.

================================================================================
DOWNLOAD PREREQUISITES
================================================================================

Install the official Hugging Face CLI once:

  pip install -U "huggingface_hub[cli]"

Then download a model file with:

  hf download REPOSITORY_ID FILENAME --local-dir "models\8GB"

The current official CLI command is "hf download". The --local-dir option puts
the GGUF in this folder and maintains download metadata in a local .cache
folder so repeat downloads can resume/update efficiently.

If the source repository is gated, authenticate first:

  hf auth login

You must also accept the repository's access terms in your Hugging Face account
when the model publisher requires it.

VERIFY BEFORE LAUNCHING
================================================================================

From the project root, confirm the file exists:

  dir "models\8GB\Qwen3.5-9B-Uncensored-HauhauCS-Aggressive-Q4_K_M.gguf"

Then open start.bat and confirm:

  set "TIER=8"

Finally double-click:

  start.bat

After model load, the browser should open automatically at:

  http://127.0.0.1:8080/

Run status.bat in a separate window for live GPU VRAM, temperature, power,
CPU/RAM, request state, and available throughput metrics.

================================================================================
OPTIONAL ALTERNATIVE MODELS
================================================================================

You may place other GGUF files in this folder, but start.bat will NOT select
them automatically. To use another model, edit this variable in start.bat:

  set "MODEL_8GB=models\8GB\YOUR_EXACT_FILENAME.gguf"

Recommended selection criteria for an 8 GB / 64K configuration:

  - Prefer models whose GGUF fits comfortably with room for the 64K KV cache.
  - Prefer Q4 / IQ4-style quantizations when model weights are near VRAM limits.
  - Test 64K explicitly; a model that loads at 8K may fail at 64K.
  - Dense models are usually easier to predict than large MoE files on 8 GB.
  - Do not choose a model only because its active MoE parameter count is small:
    all expert weights still need to be stored somewhere.

If startup produces CUDA out-of-memory while 64K must remain enabled:

  1. Set CACHE_K_8GB=q4_0 and CACHE_V_8GB=q4_0 in start.bat.
  2. Set BATCH_8GB=64 and UBATCH_8GB=64.
  3. Use a smaller GGUF/model.
  4. Lower GPU_LAYERS_8GB only if CPU offload is acceptable.

================================================================================
USB / LOAD MODE NOTES
================================================================================

The current llamafile 0.10.5 launcher can use --no-mmap when enabled in
start.bat. This can help compatibility on some removable drives, but it is not
universally faster and may use more system RAM.

Test both values in start.bat on the target USB drive:

  set "USE_NO_MMAP=1"   = passes --no-mmap
  set "USE_NO_MMAP=0"   = uses normal memory-mapped loading

Do NOT use --load-mode none with llamafile 0.10.5. That binary rejects the
newer --load-mode argument.

NOTES
================================================================================

- Model weights in this folder are never committed to Git.
- The llamafile executable belongs in server\, not in this folder.
- The local server is intentionally bound to 127.0.0.1 by default.
- Keep start.bat open while using the server; Ctrl+C stops the server.
- Exact GPU layer-offload results appear once in the start.bat startup log.
- The 8 GB profile is not a guarantee that every 8 GB GPU can fully offload
  every future model at 64K. Test the precise GGUF and settings together.
