================================================================================
AI Pendrive - 4 GB and 6 GB VRAM Models
================================================================================

This folder contains the designated compact GGUF model used by BOTH of these
current start.bat profiles:

  TIER=4  -> 4 GB VRAM preset
  TIER=6  -> 6 GB VRAM preset

Current start.bat model paths:

  MODEL_4GB=models\4GB\Gemma-4-E4B-Uncensored-HauhauCS-Aggressive-Q2_K_P.gguf
  MODEL_6GB=models\4GB\Gemma-4-E4B-Uncensored-HauhauCS-Aggressive-Q2_K_P.gguf

This is intentional: the 6 GB profile currently reuses the 4 GB model but
requests more GPU layers and CPU threads. You do not need a models\6GB\ folder
unless you later add a separate 6 GB model and change MODEL_6GB in start.bat.

The current launcher is intentionally simple:

  - It does NOT download models automatically.
  - It does NOT scan this folder and offer a model picker.
  - It does NOT auto-detect your GPU.
  - You choose the preset yourself with set "TIER=4" or set "TIER=6".

================================================================================
WHO THIS IS FOR
================================================================================

Use TIER=4 for NVIDIA GPUs with around 4 GB dedicated VRAM.

Use TIER=6 for NVIDIA GPUs with around 6 GB dedicated VRAM. It currently loads
the same GGUF from this folder but uses a less conservative GPU-layer target.

Examples of potential target hardware include GTX 1650/1650 Ti, GTX 1050 Ti,
GTX 1060 6 GB, RTX 2060 6 GB, RTX 3050 6 GB, and similar NVIDIA GPUs.

The default configuration uses:

  Context window:  64K tokens (CTX=65536)
  Parallel slots:  1
  KV cache:        q8_0 for keys and values
  Flash Attention: on
  Metrics:         enabled for status.bat

64K context is an aggressive requirement for 4 GB and 6 GB VRAM. It may require
partial CPU offload, lower GPU layers, Q4 KV cache, a smaller GGUF, or all of
these. The exact result depends on model architecture, quantization, GPU driver,
background VRAM consumption, and available system RAM.

================================================================================
DOWNLOAD PREREQUISITES
================================================================================

Install the official Hugging Face CLI once:

  pip install -U "huggingface_hub[cli]"

Then download a model file with:

  hf download REPOSITORY_ID FILENAME --local-dir "models\4GB"

The current official CLI command is "hf download". --local-dir writes the GGUF
to this folder and creates local download metadata in .cache\huggingface so a
repeat download can resume/update efficiently.

If the source repository is gated, authenticate first:

  hf auth login

You must also accept the repository's access terms on Hugging Face if required.

================================================================================
DOWNLOAD THE CURRENT REQUIRED MODEL
================================================================================

This custom uncensored GGUF may not be present in an upstream/base-model repo.
Open its Hugging Face model page and copy BOTH values exactly:

  1. Repository ID
  2. GGUF filename

Then, FROM THE AI Pendrive project root, run:

  hf download <REPOSITORY_ID> ^
    "Gemma-4-E4B-Uncensored-HauhauCS-Aggressive-Q2_K_P.gguf" ^
    --local-dir "models\4GB"

Example template only - replace <REPOSITORY_ID> with the verified model repo:

  hf download <REPOSITORY_ID> ^
    "Gemma-4-E4B-Uncensored-HauhauCS-Aggressive-Q2_K_P.gguf" ^
    --local-dir "models\4GB"

Do not substitute a Q4 filename, base model, or different publisher build unless
you also change the exact MODEL_4GB and MODEL_6GB variable values in start.bat.

================================================================================
VERIFY BEFORE LAUNCHING
================================================================================

From the project root, confirm the exact file exists:

  dir "models\4GB\Gemma-4-E4B-Uncensored-HauhauCS-Aggressive-Q2_K_P.gguf"

Select one target preset in start.bat:

  set "TIER=4"

or:

  set "TIER=6"

Then double-click:

  start.bat

When the server finishes loading, the browser opens automatically at:

  http://127.0.0.1:8080/

Run status.bat in a separate window for live GPU VRAM, temperature, power,
CPU/RAM, request state, and available throughput metrics.

================================================================================
4 GB VS 6 GB PROFILE BEHAVIOR
================================================================================

  TIER      Model folder   Model file          GPU layer target   CPU threads
  --------  -------------  ------------------  -----------------  -----------
  4         models\4GB     designated Q2_K_P   18                 6
  6         models\4GB     designated Q2_K_P   32                 8

The GPU-layer target is a request, not a guarantee. Llamafile prints the final
actual GPU/CPU layer split in start.bat startup logs.

For full 64K context, avoid raising PARALLEL above 1. More parallel server slots
split available context/resources among simultaneous requests.

================================================================================
OPTIONAL ALTERNATIVE MODELS
================================================================================

You can store other GGUF files in this folder, but start.bat will NOT discover
or choose them automatically. To use an alternative, explicitly edit both paths
that should use it:

  set "MODEL_4GB=models\4GB\YOUR_EXACT_FILENAME.gguf"
  set "MODEL_6GB=models\4GB\YOUR_EXACT_FILENAME.gguf"

For 4 GB and 6 GB systems with a fixed 64K context requirement:

  - Prefer compact models and low-bit GGUF quantizations.
  - Verify the model supports the desired context length.
  - A model that fits at 4K or 8K may fail at 64K because KV cache grows with
    context size.
  - Avoid assuming a 6 GB GPU can run any 6 GB GGUF at 64K; runtime buffers and
    KV cache also require memory.
  - MoE models can still be large in memory because their total expert weights
    must be stored, even though only some experts activate per token.

If 64K launch fails and you must preserve 64K:

  1. Change CACHE_K_4GB/CACHE_V_4GB or CACHE_K_6GB/CACHE_V_6GB to q4_0.
  2. Change BATCH_4GB/UBATCH_4GB or BATCH_6GB/UBATCH_6GB to 64.
  3. Select a smaller GGUF/model.
  4. Lower GPU_LAYERS_4GB or GPU_LAYERS_6GB only if CPU offload is acceptable.

================================================================================
USB / LOAD MODE NOTES
================================================================================

The current llamafile 0.10.5 launcher can use --no-mmap when enabled in
start.bat. This can help compatibility on some removable drives, but it is not
universally faster and can use more system RAM.

Test both values in start.bat on the actual USB drive:

  set "USE_NO_MMAP=1"   = passes --no-mmap
  set "USE_NO_MMAP=0"   = normal memory-mapped loading

Do NOT use --load-mode none with llamafile 0.10.5. That executable rejects the
newer --load-mode argument.
